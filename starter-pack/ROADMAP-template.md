# ROADMAP Template

Use this document to define phased product direction.

The roadmap should explain:

- where the project is now
- what the next phase accomplishes
- how progress is measured
- what is intentionally delayed

Avoid vague roadmap items like:

- improve UX
- optimize backend
- polish app

Every phase should produce a measurable outcome.

# Roadmap Rules

- Separate MVP from expansion.
- Keep phases outcome-based.
- Keep future ideas isolated from current scope.
- Update roadmap when strategic direction changes.
- Avoid fake roadmap theater.

The roadmap should help decision-making, not just look impressive.
