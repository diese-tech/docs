# MVP Readiness Checklist

Use this before calling a product "MVP complete."

The goal is to verify the product is actually usable, understandable, and operable.

---

# Core Workflow

- [ ] Primary user workflow works end-to-end
- [ ] User can complete the intended outcome
- [ ] Errors are surfaced clearly
- [ ] App does not require hidden manual intervention

---

# Product Clarity

- [ ] Product purpose is understandable
- [ ] Core workflow is understandable
- [ ] User confusion points identified
- [ ] Major scope creep avoided

---

# Operational Readiness

- [ ] Logging exists
- [ ] Major failures are observable
- [ ] Rollback path understood
- [ ] Environment setup documented
- [ ] Deployment path tested

---

# Documentation

- [ ] README exists
- [ ] MVP scope documented
- [ ] ROADMAP exists
- [ ] TASKS updated
- [ ] DECISIONS updated
- [ ] AI workflow guardrails exist

---

# Technical Health

- [ ] App builds successfully
- [ ] No obvious runtime errors
- [ ] Environment variables documented
- [ ] Integrations tested
- [ ] Known constraints documented

---

# Product Validation

- [ ] Real user feedback collected
- [ ] Product solves the intended problem
- [ ] Workflow usefulness validated
- [ ] Biggest unknowns identified

---

# Final Question

If a real user tried this tomorrow, would they experience:

- confidence?
- clarity?
- reduced friction?
- meaningful value?

If not, the MVP is not actually complete.
