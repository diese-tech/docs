# New Project Checklist

Use this before creating a new repo.

The goal is to prevent:

- scope chaos
- abandoned repos
- architecture drift
- undocumented assumptions
- AI implementation confusion

---

# 1. Project Validation

## Problem

- [ ] Real problem identified
- [ ] Target user identified
- [ ] Problem severity understood
- [ ] Existing alternatives reviewed

## Motivation

- [ ] Long-term interest exists
- [ ] Strategic value exists
- [ ] Monetization potential considered
- [ ] Maintenance burden considered

## Scope

- [ ] MVP defined
- [ ] Exclusions documented
- [ ] Success condition defined
- [ ] Future ideas separated from MVP

---

# 2. Repository Setup

Create:

- [ ] README.md
- [ ] AGENTS.md
- [ ] MVP.md
- [ ] ROADMAP.md
- [ ] TASKS.md
- [ ] DECISIONS.md
- [ ] docs/AI_WORKFLOW_GUARDRAILS.md

Optional:

- [ ] OPERATIONS.md
- [ ] RELEASE_PROCESS.md
- [ ] CODEBASE_WALKTHROUGH.md

---

# 3. Technical Decisions

- [ ] Stack chosen intentionally
- [ ] Hosting approach chosen
- [ ] Persistence strategy chosen
- [ ] Auth requirements evaluated
- [ ] Operational complexity understood
- [ ] External dependencies reviewed

---

# 4. AI Workflow Preparation

Before AI-assisted implementation:

- [ ] Product priorities documented
- [ ] Out-of-scope features documented
- [ ] Architecture rules documented
- [ ] Guardrails reviewed
- [ ] Implementation philosophy established

---

# 5. Operational Thinking

- [ ] Failure modes considered
- [ ] Rollback approach considered
- [ ] Logging/observability needs considered
- [ ] Scaling risks identified
- [ ] Maintenance burden understood

# Final Rule

Do not build projects because they are exciting.

Build projects because they solve meaningful problems, teach valuable skills, support long-term goals, or create real leverage.
